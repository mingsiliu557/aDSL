## Image 为什么低：实际请求与裁决不同

1. `run_paired.py::image_payload()` 的离线审核只给原 prompt 和最终图片；明确清空 checklist、历史和 Code Critic corrections，也不读源码。
2. 在线生成的 Image 有 plan/checklist、轮次/历史及 Code 纠偏。Image 拒绝后调用 Code；Code 可以放行而结束生成。当前 Code prompt 明确要求优先信代码逻辑，Image prompt 则要求服从 Code 纠偏。
3. wo 六个最终保留版本全部是 **Image=false、Code=true、appearance_approved=true**。所以“生成审核通过”与表里的“独立 Image FAIL”并不矛盾，它们本来不是同一个字段。
4. w/SF07 在线最终 Image=true，离线则因表面分面/带状伪影而拒绝。同一几何的不同上下文评审不一致；不能据此认定哪个一定正确，也不存在本次偷偷上调的数值阈值。

| 案例 | wo 离线 Image 记录的主要问题 | w 离线 Image 记录的主要问题 |
|---|---|---|
| SF07 | 桌面上方尖状突出，不是平滑可用表面 | 表面分面、水平条带/轮廓伪影，光滑高光要求不满足 |
| SF03 | 木色与孤立黑短划线不像连贯木纹 | 靠背立柱/横梁出现黑缝、裁缺或错位观感 |

这是验证器意见归纳，不是新增人工判图。记录同时暴露了代码覆核的局限：例如 SF03/w Code 以“源码立柱/横梁连续、没有减料”判显示伪影；现有逐阶段网格诊断却确实在 Boolean 结果中测到退化。因此不能仅用源码设计意图证明最终求值几何正确。当前仅说明这一冲突，未改提示或裁决逻辑。
